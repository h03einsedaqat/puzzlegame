# فهرست انتشار در کافه‌بازار — کلمه‌ساز

این فهرست بر پایه مستندات رسمی کافه‌بازار نوشته شده است (منابع و جدول «ثابت/متغیر»
در `docs/PROJECT_PLAN.md` بخش ۲). هر موردی که در مستندات رسمی عدد یا قانون قطعی
ندارد، با **NEEDS VERIFICATION BEFORE RELEASE** علامت خورده است؛ هیچ قانون ساختگی
به بازار نسبت داده نشده.

---

## ۱) هویت برنامه

- [x] نام برنامه: **کلمه‌ساز** (۸ کاراکتر؛ کمتر از ۱۶ کاراکتر، پس در همه دستگاه‌ها
      کامل نمایش داده می‌شود — سقف مجاز ۱۰۰ کاراکتر است)
- [x] نام بسته: `ir.kalamesaz.game` — قالب `topleveldomain.companyname.applicationname`،
      فقط حروف کوچک/عدد/`_`، هر بخش با حرف شروع می‌شود، بدون `-`
      → **پس از اولین انتشار قابل تغییر نیست؛ همین مقدار نهایی فرض شده است**
- [x] نسخه: `versionName = 1.0.0` و `versionCode = 1` در `android/app/build.gradle`
- [x] تطابق با `APP_INFO` در `src/constants/appInfo.ts` (نام، نسخه، بسته، ایمیل پشتیبانی)
- [ ] ایمیل پشتیبانی واقعی و فعال در `APP_INFO.contactEmail` و در پیشخان بازار ثبت شود

## ۲) بسته و امضا

- [x] ساخت APK/AAB: `npm run android:apk:release` / `npm run android:aab:release`
- [x] پیکربندی امضا از `android/keystore.properties` خوانده می‌شود (فایل در git نیست)
- [x] نمونه پیکربندی: `android/keystore.properties.example`
- [ ] ساخت کلید انتشار (یک‌بار): `keytool -genkeypair` — دستور کامل در `docs/BUILD_AND_RUN.md`
- [ ] نگه‌داری امن کلید و رمزها بیرون از مخزن (پشتیبان رمزگذاری‌شده)
- [ ] امضای همان کلید در همه نسخه‌های بعدی (تغییر کلید = رد شدن به‌روزرسانی)
- [x] `enableProguardInReleaseBuilds` روی `false` است تا کوچک‌سازی بدون تست کامل روشن نشود
- [ ] پیش از انتشار نهایی: `enableProguardInReleaseBuilds = true` و یک چرخه تست کامل
      روی بسته کوچک‌شده (باز شدن همه صفحه‌ها، صدا، ذخیره‌سازی، بازگردانی پیشرفت)
- [x] حداکثر حجم APK مجاز بازار ۱۵۰ مگابایت است؛ بسته فعلی چند مگابایت بیشتر نیست
- [ ] **NEEDS VERIFICATION BEFORE RELEASE**: آپلود AAB و تبدیل آن با «Bundle Signer»
      بازار (فایل خروجی `.bin`) — مسیر دقیق و محدودیت‌های روز پیشخان دوباره خوانده شود
- [ ] **NEEDS VERIFICATION BEFORE RELEASE**: حداقل Target SDK اجباری روز انتشار
      (پروژه روی `targetSdk = 36` و `compileSdk = 37` است که از آخرین عدد اعلام‌شده
      در صفحه خطاهای متداول پیشخان بالاتر است)

## ۳) دسترسی‌ها و حریم خصوصی

- [x] مجوز اینترنت در بسته اصلی تعریف نشده (بازی کامل آفلاین است)
- [x] هیچ SDK تبلیغاتی، تحلیلی یا خریدی در نسخه MVP فعال نیست
- [x] هیچ داده‌ای از دستگاه بیرون نمی‌رود؛ همه چیز در حافظه محلی است
- [x] صفحه «حریم خصوصی» داخل برنامه، متن کامل و بی‌ابهام دارد
- [ ] متن «توضیح برای بررسی‌کننده» در پیشخان: توضیح دهد که بازی آفلاین است و
      هیچ داده‌ای جمع نمی‌کند — **NEEDS VERIFICATION BEFORE RELEASE** بر پایه آخرین
      نسخه سند «دلایل متداول رد برنامه‌ها»
- [ ] اگر بعداً تبلیغات یا خرید اضافه شد: به‌روزرسانی متن حریم خصوصی و اعلام SDKها
      (SDKهای شخص ثالث بخشی از برنامه محسوب می‌شوند)

## ۵) کیفیت پیش از ارسال

- [ ] `npm run verify` سبز است (typecheck + lint + test)
- [ ] `npm run levels:check` سبز است (همه ۵۰ مرحله و ۶۰ پازل روزانه سالم)
- [ ] آزمون روی حداقل دو دستگاه واقعی: یکی اندروید قدیمی (نزدیک API 24) و یکی جدید
- [ ] چرخه کامل بازی روی دستگاه: آموزش → مرحله ۱ → نتیجه → خانه → چالش روزانه
- [ ] بستن و باز کردن برنامه: پیشرفت، سکه، قلب و تنظیمات درست برمی‌گردد
- [ ] خروج با دکمه بازگشت اندروید در صفحه بازی، گفت‌وگوی تأیید را نشان می‌دهد
- [ ] صدا و لرزش با خاموش/روشن‌کردن تنظیمات درست رفتار می‌کنند
- [ ] چیدمان راست‌به‌چپ روی دستگاه واقعی بررسی شده (هیچ متنی بریده یا جابه‌جا نیست)
- [ ] فونت وزیرمتن در بسته هست (متن‌ها با فونت پیش‌فرض اندروید نمایش داده نمی‌شوند)
- [ ] پر شدن قلب با گذشت زمان روی دستگاه بررسی شده (بدون تغییر ساعت دستگاه)
- [ ] حالت «کاهش انیمیشن» در تنظیمات اثر واقعی دارد

## ۶) پس از انتشار

- [ ] ثبت نسخه منتشرشده در `CHANGELOG.md` با شماره نسخه و تاریخ
- [ ] نگه‌داری خروجی AAB/APK هر نسخه برای مرجع
- [ ] پاسخ‌گویی به دیدگاه‌های کاربران از همان ایمیل پشتیبانی
- [ ] پایش خطاهای گزارش‌شده و برنامه‌ریزی نسخه بعدی (محتوای تازه، لایه‌های راهنمای
      باقی‌مانده، فعال‌سازی خرید در صورت تصمیم)

## ۷) گام‌به‌گام انتشار در پیشخان

1. ورود به پیشخان توسعه‌دهندگان کافه‌بازار و ساخت «برنامه تازه».
2. ثبت نام بسته `ir.kalamesaz.game` (پیش از این با پیکربندی پروژه یکسان است).
3. بارگذاری بسته: AAB یا APK امضاشده.
4. پر کردن نام، توضیح کوتاه و کامل (از `docs/STORE_LISTING.md`)، دسته‌بندی و آیکون
   ۵۱۲×۵۱۲.
5. بارگذاری اسکرین‌شات‌ها (۵ تا ۸ تصویر از `docs/SCREENSHOT_PLAN.md`).
6. نوشتن یادداشت بررسی‌کننده: بازی کاملاً آفلاین است، مجوز خاصی نمی‌خواهد و هیچ
   داده‌ای جمع نمی‌کند.
7. ثبت انتشار. بررسی و انتشار برنامه‌های تازه معمولاً تا ۳ روز کاری زمان می‌برد
   (پنجشنبه و جمعه در این شمارش نیستند). گزینه «انتشار خودکار» را در صورت تمایل
   روشن کن.
8. پس از انتشار: به‌روزرسانی `CHANGELOG.md` و آماده‌سازی نسخه بعدی با همان کلید امضا.

> یادآوری: هر تغییری در قوانین بازار که پس از تاریخ این سند اعلام شود، بر این
> فهرست اولویت دارد. موارد «NEEDS VERIFICATION» پیش از ارسال نهایی باید از پیشخان
> یا پشتیبانی بازار استعلام شوند.
