# نصب نشدن برنامه روی گوشی — خطای «App not installed as package appears to be invalid»

این پیام را اندروید وقتی می‌دهد که فایلی را که لمس کرده‌ای «بسته نصبی معتبر» نمی‌داند.
ترجمهٔ تحت‌اللفظی‌اش («بسته به‌نظر نامعتبر است») گمراه‌کننده است: تقریباً هیچ‌وقت
یعنی داخل برنامه مشکلی هست. در عمل یکی از این چند چیز است:

| نشانه | علت | راه‌حل |
| --- | --- | --- |
| **همه‌جا** (هر گوشی‌ای) نصب نمی‌شود، خطا سریع می‌آید | **نبود امضای v1 (JAR) در APK** — AGP وقتی `minSdkVersion ≥ 24` باشد آن را خودش خاموش می‌کند و بعضی نصب‌کننده‌های گوشی (و فایل‌منیجرهایی که خودشان APK را می‌خوانند) فقط امضای v1 را می‌خوانند | نسخه‌ای که با `enableV1Signing true` ساخته شده را دانلود کن (این اصلاح از این پس در همه ساخت‌ها اعمال است) |
| فایل از چیزی که باید کوچک‌تر است؛ با وای‌فای/دانلود‌منیجر یا در شبکه فیلترشده گرفته شده | **دانلود ناقص یا خراب** — بلوک امضا در آخرین کیلوبایت‌های فایل است، پس دانلود نصفه‌کاره هم همین پیام را می‌دهد | حجم و SHA-256 را بسنج (بخش ۱) و فایل را دوباره بگیر |
| فقط روی یکی از چند گوشی نصب نمی‌شود | اندروید قدیمی‌تر از ۷، یا نسخه قبلی با **کلید امضای دیگر** روی گوشی نصب است | بخش ۲ |
| خطا وسط نصب یا هنگام اسکن Play Protect می‌آید | Play Protect / نداشتن اجازه «نصب از منابع نامعلوم» / کمبود فضا | بخش ۳ |
| فایلی که دانلود کرده‌ای `.zip` است (مثلاً `kalamesaz-apk.zip`) | آن **آرتیفکت Actions** است، نه APK | zip را باز کن و `app-release.apk` داخلش را نصب کن، یا از صفحه Releases همان `.apk` را بگیر |

## ۱) اول حجم و SHA-256 فایل را بسنج (تشخیص دانلودِ ناقص)

روی صفحه [Releases](../../releases) در توضیحات بسته، **حجم دقیق** (و در ساخت‌هایی که با
گردش‌کار تازه ساخته می‌شوند، **SHA-256** به‌همراه فایل `<نام بسته>.sha256`) نوشته شده
است. اگر حجم فایل دانلودشده با آن عدد یکی نبود، دانلود ناقص است و همین باعث خطا
می‌شود؛ فایل را دوباره بگیر.

```bash
# لینوکس / مک — حجم فایل را با عدد صفحه Releases بسنج
wc -c < kalamesaz-2.0.0-arm.apk
# ویندوز (PowerShell)
(Get-Item .\kalamesaz-2.0.0-arm.apk).Length
```

```bash
# لینوکس / مک
sha256sum kalamesaz-2.0.0-arm.apk

# ویندوز (PowerShell یا CMD)
certutil -hashfile kalamesaz-2.0.0-arm.apk SHA256
```

اگر روی خودِ گوشی هستی، از یک اپ «checksum» (مثل Hash Checker) استفاده کن، یا فایل را
با کابل به رایانه بفرست و دستور بالا را اجرا کن.

> **نکته مهم برای شبکه‌های ناپایدار/فیلترشده:** مرورگرهای موبایل اغلب دانلود ۳۰ مگابایتی
> را نصفه ذخیره می‌کنند و هیچ پیامی هم نمی‌دهند. راه مطمئن، دانلود «قابل ادامه» است:

```bash
# تا کامل‌شدن فایل، همین دستور را تکرار کن (از نصفه ادامه می‌دهد)
until curl -C - -L --retry 5 --retry-all-errors \
  -o kalamesaz-2.0.0-arm.apk \
  https://github.com/<کاربر>/<مخزن>/releases/download/apk-latest/kalamesaz-2.0.0-arm.apk; do
  echo "ادامه دانلود..." ; sleep 2
done
sha256sum kalamesaz-2.0.0-arm.apk   # باید با عدد صفحه Releases یکی باشد
```

اگر `gh` نصب داری، این یک خط ساده‌ترین راه است (فایل را با ادامه دانلود می‌گیرد):

```bash
gh release download apk-latest --clobber
```

اگر شبکه‌ات گیت‌هاب را ناقص می‌دهد، از VPN یا DNS/پروکسی مطمئن استفاده کن؛ خودِ فایل
روی سرور گیت‌هاب سالم است (بخش ۴ را ببین).

## ۲) اگر فایل سالم است، این‌ها را روی گوشی بررسی کن

1. **نسخه اندروید**: این بازی به اندروید **۷.۰ (API 24) یا بالاتر** نیاز دارد
   (Settings → About phone → Android version).
2. **نسخه قبلی با امضای دیگر**: اگر قبلاً نسخه‌ای از همین بازی را (مثلاً ساختی روی
   رایانه خودت یا از صفحه Releases) نصب کرده‌ای، اندروید اجازه نمی‌دهد نسخه‌ای با کلید
   دیگر رویش بنشیند. اول حذفش کن:
   ```bash
   adb uninstall ir.kalamesaz.game
   ```
   یا از Settings → Apps → کلمه‌ساز → Uninstall.
   (نسخه دیباگ با شناسه `ir.kalamesaz.game.debug` برنامه جداگانه‌ای است و بی‌ربط است.)
3. **اجازه نصب**: Settings → Apps → Special access → Install unknown apps → همان
   برنامه‌ای که APK را باز می‌کند (فایل‌منیجر/مرورگر) باید مجاز باشد.
4. **Play Protect**: Play Store → پروفایل → Play Protect → ⚙ → «Scan apps with Play
   Protect» را موقتاً خاموش کن، نصب کن، بعد دوباره روشن کن.
5. **فضا**: برای یک بسته ۳۷ مگابایتی، حدود ۱۰۰ مگابایت فضای خالی لازم است.
6. **برندهای MIUI/EMUI/ColorOS**: «MIUI optimization» یا نصب از فایل‌منیجر شخص ثالث
   گاهی جلوی نصب را می‌گیرد؛ با یک فایل‌منیجر دیگر (مثلاً Files خود گوگل) امتحان کن.
7. گوشی را یک‌بار ری‌استارت کن؛ گاهی Package Installer گیر می‌کند.

## ۳) پیام دقیق خطا را بگیر (سریع‌ترین راه تشخیص)

نصب از طریق `adb` کد خطای واقعی را نشان می‌دهد و حدس‌وگمان را تمام می‌کند:

```bash
adb install -r kalamesaz-2.0.0-arm.apk
```

| کد خطا | معنی | کار |
| --- | --- | --- |
| `INSTALL_PARSE_FAILED_NO_CERTIFICATES` | بسته امضایی ندارد یا امضایش خوانده نمی‌شود | نسخه تازه (با امضای v1+v2) را بگیر؛ اگر باز هم بود، دانلود ناقص است |
| `INSTALL_FAILED_INVALID_APK` | فایل خراب/ناقص است | حجم و SHA-256 را بسنج و دوباره دانلود کن |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | نسخه نصب‌شده با کلید دیگری امضا شده | `adb uninstall ir.kalamesaz.game` |
| `INSTALL_FAILED_OLDER_SDK` | اندروید گوشی قدیمی‌تر از ۷ است | روی گوشی جدیدتر نصب کن |
| `INSTALL_FAILED_NO_MATCHING_ABIS` | فایل برای معماری گوشی تو نیست | بسته `kalamesaz-2.0.0-arm.apk` هر دو معماری ARM را دارد؛ مطمئن شو همین فایل را گرفته‌ای |
| `INSTALL_FAILED_INSUFFICIENT_STORAGE` | فضا کم است | فضا آزاد کن |

## ۴) خودِ فایل را روی رایانه بررسی کن

این پروژه یک ابزار دارد که همین کارهایی را می‌کند که اندروید هنگام نصب می‌کند
(سالم بودن zip، ترازبندی، امضای v1/v2/v3، خواندنی بودن مانیفست و معماری‌ها):

```bash
bash tools/verify-apk.sh kalamesaz-2.0.0-arm.apk
# یا اگر Android SDK Build-Tools را جای دیگری داری:
bash tools/verify-apk.sh kalamesaz-2.0.0-arm.apk ~/Android/Sdk/build-tools/36.0.0
```

اگر نتیجه‌اش «بسته سالم و نصب‌شدنی است» بود ولی گوشی باز هم خطا داد، فایل را روی همان
گوشی مشکل‌دار بگذار و ببین بخش ۳ چه کد خطایی می‌دهد.

روی سرور گیت‌هاب هم گردش‌کار `Verify published APK` همین بررسی را روی همان فایلی که
منتشر شده انجام می‌دهد و گزارش را در `docs/ci-reports/` می‌گذارد (فایل
`docs/ci/apk-verify.yml` را یک‌بار در `.github/workflows/` کپی کن — بخش ۳ سند
`BUILD_AND_RUN.md`).

## پیوست فنی: چرا امضای v1؟

- اندروید ۷ (API 24) به بعد امضای **v2** دارد و بسته‌ای که فقط v2 داشته باشد از نظر
  خودِ اندروید سالم است.
- ولی AGP وقتی `minSdkVersion ≥ 24` باشد امضای **v1 (JAR)** را به‌طور پیش‌فرض خاموش
  می‌کند. بعضی نصب‌کننده‌های اختصاصی گوشی‌ها، فایل‌منیجرها و سرویس‌های فروشگاهی
  (و همچنین دستگاه‌ها/رام‌هایی که فقط مسیر قدیمی امضا را می‌خوانند) بسته‌ای که بلوک
  v1 نداشته باشد را «معتبر» نمی‌دانند و همان پیام
  «App not installed as package appears to be invalid» را نشان می‌دهند.
- این پروژه پیش‌تر همین وضعیت را داشت؛ چون در `android/app/build.gradle` مقدار
  `minSdkVersion` روی ۲۴ بود و هیچ‌جا `enableV1Signing` روشن نشده بود (قالب خود
  React Native هم آن را روشن نمی‌کند).
- از این پس هر دو کلید `enableV1Signing true` و `enableV2Signing true` روی پیکربندی
  امضا تنظیم است. هزینه‌اش چند کیلوبایت بزرگ‌تر شدن فایل است و فایده‌اش نصب‌شدن روی
  دامنه وسیع‌تری از گوشی‌ها؛ برعکس، هیچ گوشی‌ای از وجود بلوک v1 ضرر نمی‌کند.

**امضا عوض نشده است:** همان کلید (`debug.keystore` مخزن) است، پس نصب‌های قبلی هم
در جای خودشان به‌روز می‌شوند.

## اگر همچنان نصب نشد

این سه چیز را بفرست تا دقیقاً مشخص شود:

1. مدل گوشی و نسخه اندروید (Settings → About phone)
2. حجم دقیق فایلِ دانلودشده و مقدار `sha256sum` آن
3. خروجی `adb install -r <file>.apk`
