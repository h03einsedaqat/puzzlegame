# کلمه‌ساز — سند برنامه و تصمیم‌های فنی

آخرین به‌روزرسانی این سند: ۲۰۲۶-۱۰-۰۶ (۱۴۰۵/۰۷/۱۴)

این سند پیش از شروع کدنویسی نوشته شده و مبنای تصمیم‌های پروژه است. هر عددی که در
پروژه استفاده شده، از منبع رسمی گرفته شده و منبع آن در همین سند ذکر شده است.
هر موردی که ممکن است در آینده تغییر کند با برچسب **NEEDS VERIFICATION BEFORE RELEASE**
علامت خورده و در `BAZAAR_RELEASE_CHECKLIST.md` هم تکرار شده است.

**تصمیم‌های آگاهانه‌ی «نه»:**

- **react-native-reanimated استفاده نشد.** انیمیشن‌های این بازی (pop، shake، fly)
  با `Animated` و درایور بومی (native driver) کافی و روان هستند. حذف Reanimated
  یک وابستگی بومی حساس (worklets + CMake) کم می‌کند و ریسک Build را پایین می‌آورد.
- **react-native-gesture-handler استفاده نشد.** هیچ ژست پیچیده‌ای در بازی نیاز نیست
  و native-stack به آن وابسته نیست.

### درباره صدا

پخش صدای واقعی روی Android نیازمند یک ماژول بومی است. برای اینکه Build اول
پروژه بدون ریسک باشد، لایه صدا به‌صورت `SoundService` با معماری Backend نوشته شده
است: پیاده‌سازی پیش‌فرض بدون وابستگی بومی کار می‌کند (و فقط در حالت توسعه لاگ
می‌دهد) و با نصب یک پکیج صدا، بدون تغییر در کد بازی فعال می‌شود. مسیر فعال‌سازی در
README آمده است.

### موارد متغیر — **NEEDS VERIFICATION BEFORE RELEASE**

1. **حداقل Target SDK اجباری بازار.** صفحه «راهنمای خطاهای متداول پیشخان» متن خطای
   `APK sdk version is below 32` را آورده است، اما تاریخ به‌روزرسانی آن صفحه قدیمی‌تر
   از امروز است و عدد قطعی جاری در مستندات رسمی نیامده. تصمیم فنی پروژه روی
   **targetSdk = 36** گرفته شده که بالاتر از هر عدد اعلام‌شده است؛ پیش از انتشار
   باید عدد جاری از پیشخان/پشتیبانی بازار استعلام شود.
2. **الزامات جدید امضا و انتشار (Signing / رهانش).** سرویس‌های امضای بازار و
   قوانین رهانش تدریجی در حال تغییرند؛ پیش از انتشار باید صفحه‌های مرتبط دوباره
   خوانده شود.
3. **قوانین تبلیغات درون‌برنامه‌ای.** مستندات رسمی «تبلیغات» بازار درباره کمپین
   تبلیغاتی خودِ برنامه در بازار است، نه شبکه‌های تبلیغاتی داخل برنامه. فهرست
   SDKهای تبلیغاتی مجاز/غیرمجاز و محدودیت‌های آن‌ها **NEEDS VERIFICATION** است.
4. **خرید درون‌برنامه‌ای.** کتابخانه رسمی پولکی (Poolakey، Apache-2.0، نسخه
   ۲.۲.۰) و ریپوی رسمی `cafebazaar/react-native-poolakey` وجود دارد، اما پیش از
   فعال‌سازی پرداخت باید نسخه، نحوه دریافت کلید عمومی از پیشخان و قوانین
   محصولات مصرفی/اشتراک دوباره بررسی شود.
5. **الزامات Privacy / Data Safety.** بازار فرم مدونی مانند Google Play Data
   Safety ندارد؛ متن حریم خصوصی و «توضیحات بیشتر برای بررسی‌کننده» باید بر اساس
   آخرین نسخه سند «دلایل متداول رد برنامه‌ها» نوشته شود.
6. **الزامات کیفی/محتوایی به‌روز.** صفحه «دلایل متداول رد برنامه‌ها» مرجع نهایی
   است و باید پیش از انتشار بازخوانی شود.

هیچ‌کدام از این شش مورد با حدس پر نشده‌اند؛ در پروژه به‌عنوان «قابل تغییر» علامت
خورده‌اند و به آن‌ها عدد یا قانون ساختگی نسبت داده نشده است.

## ۳. تصمیم‌های معماری

1. **UI نازک، منطق ضخیم.** هیچ قانون بازی داخل JSX نیست. `gameEngine.ts` توابع
   خالص دارد و کامپوننت‌ها فقط رندر می‌کنند.
2. **هسته بازی خالص و تست‌پذیر.** `gameEngine`، `wordValidator`، `heartRegenerator`،
   `dailySeed`، `levelValidator` بدون هیچ وابستگی به React و AsyncStorage هستند.
3. **سرویس‌ها پشت اینترفیس.** `AdService`، `AnalyticsService`، `PurchaseService`،
   `SoundService`، `VibrationService` همگی اینترفیس دارند و پیاده‌سازی No-op/محلی
   دارند؛ افزودن SDK واقعی بعداً بدون دست‌زدن به UI انجام می‌شود.
4. **ذخیره‌سازی متمرکز.** هیچ Screen‌ای مستقیم با AsyncStorage حرف نمی‌زند. لایه
   `services/storage` مسئول کلیدها، نسخه‌بندی، مهاجرت و بازیابی پس از خرابی داده
   است.
5. **آفلاین‌فرست.** دیکشنری، مرحله‌ها، پیشرفت و چالش روزانه همه محلی‌اند. برنامه
   در نسخه MVP به هیچ سروری نیاز ندارد (مجوز INTERNET فقط در Build دیباگ است).
6. **RTL واقعی.** همه سبک‌ها از `start/end` و `direction: 'rtl'` استفاده می‌کنند؛
   `forceRTL` هم برای اجزای بومی تنظیم می‌شود.
7. **اقتصاد بازی در یک فایل.** همه اعداد اقتصاد در `constants/gameConfig.ts` است.
8. **تولید مرحله‌ها با اسکریپت + اعتبارسنجی تستی.** مرحله‌ها با
   `tools/build-levels.mjs` از دیکشنری تولید و با تست `validateLevel` روی هر ۵۰+
   مرحله اعتبارسنجی می‌شوند تا هیچ مرحله غیرقابل‌حل یا تکراری وارد بازی نشود.

## ۴. ساختار پوشه‌ها

ساختار پروژه مطابق درخواست و در `README.md` مستند شده است. اصول:

- `src/types/*` مدل‌های دامنه.
